企业知识库系统 - 技术架构文档

一、系统概述
本系统是一个基于RAG（检索增强生成）技术的企业知识库智能问答系统。
RAG技术结合了信息检索和文本生成的优势，能够有效解决大语言模型的知识时效性和准确性问题。

二、核心技术原理
1. 文档向量化（Embedding）
   - 使用预训练的深度学习模型将文本转换为高维向量
   - 语义相近的文本在向量空间中距离更近
   - 本项目使用BGE-Small-ZH中文模型，模型大小约100MB
   - 向量维度为512维

2. 向量存储与检索
   - 将文档分片后的向量存储在向量数据库中
   - 查询时将问题也转换为向量
   - 通过余弦相似度计算找到最相关的文档片段
   - 当前使用InMemoryEmbeddingStore，适合开发和中小规模使用

3. RAG流程
   a. 用户提出问题
   b. 将问题向量化
   c. 在向量库中搜索Top-K个最相关的文档片段
   d. 将检索到的文档片段作为上下文，与问题一起构建Prompt
   e. 调用大语言模型生成回答
   f. 返回结果给用户

4. 文档分片策略
   - 使用递归分片器（RecursiveDocumentSplitter）
   - 分片大小：200字符
   - 重叠大小：50字符
   - 保持段落完整性，避免切断句子

三、内存占用分析
- Spring Boot基础：约200MB
- 嵌入模型（BGE-Small-ZH ONNX版）：约100MB
- LLM客户端：约50MB
- 向量存储（2个文档）：约10MB
- JVM开销：约150MB
- 总计：约500MB（16GB内存完全够用）

四、API接口设计
1. POST /api/chat - 智能问答
   请求：{"message": "用户问题"}
   响应：{"success": true, "answer": "AI回答"}

2. POST /api/upload - 上传文档
   请求：multipart/form-data，file字段
   响应：{"success": true, "message": "处理结果"}

3. GET /api/documents - 文档列表
   响应：{"success": true, "documents": ["文件1", "文件2"]}

4. DELETE /api/documents/{filename} - 删除文档
